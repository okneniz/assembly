# tests/

Integration tests and the project's test infrastructure. Full run of all
gates with one command from the repository root:

```bash
make tests
```

The chain: `docker` (the toolchain gates inside a Linux container: `examples`
→ `test` → `rt-run`) → `rt-vm` (the behavioral VM matrix on the host, QEMU).
Running a specific target: `make -C tests <target>` - all targets and their
descriptions are in the [Makefile](Makefile).

## Toolchain split

Everything that needs an LLVM/clang install runs inside the docker container
(`docker/Dockerfile`, the engine is colima) - nothing toolchain-related has
to be installed on the personal machine:

- **container**: clang (the riscv example + parser-test fixtures, one
  multi-target binary), llvm-mc / llvm-objdump / llvm-readelf - the oracles
  of the differential and property tests;
- **host**: qemu-system-aarch64 / qemu-system-riscv64 /
  qemu-system-loongarch64 - `TestHelloVM` and the `rt-vm` VM matrix
  (`rt-vm` also needs the downloaded `corpus/vm/cache` kernels/minirootfs);
- **host, once**: `brew install colima` + `colima start` - the docker
  engine. The Makefile pins `--context colima`, so a running Docker Desktop
  does not take the builds silently.

The QEMU-dependent tests skip inside the container (the image has no
emulator) and run on the host instead; the LLVM-oracle tests do the
reverse. `make tests` covers both halves.

## What lives here

- `assembly_test.go` - differential gates against llvm-objdump (Mach-O +
  ELF);
- `hello_asm_test.go` - round-trip of the hello-asm demo + `TestHelloVM`
  (QEMU);
- `matrix_vm_test.go` - the behavioral matrix in isolated VMs
  (`make -C tests rt-vm`): builds the initramfs, boots one qemu machine per
  architecture in parallel, checks the serial log;
- `cmd/` - commands and wrappers used only for tests: `assembly-diff`,
  `assembly-rt`, the `objdump/` wrapper (see [cmd/README.md](cmd/README.md));
- `docker/` - the Dockerfile of the toolchain container;
- `examples/` - test binaries and full-cycle demos (hello-world,
  hello-riscv, hello-asm);
- `vm/` - `init.sh`, the /init template of the matrix run (its `__ARCH__` is
  substituted by `matrix_vm_test.go` at image build time);
- `corpus/` - round-trip corpus (gitignored, regenerated by `rt-cli`/
  `rt-run`).

Without a required tool the corresponding step fails loudly - gates must not
stay silent; simply do not run the specific targets without it.

The loong64 VM boots the Alpine edge minirootfs snapshot (the port lives
only in edge, as dated tarballs) with the linux-lts kernel extracted from
its apk (no netboot tarball for the port); the artifacts live in
tests/corpus/vm/cache with the apk sha256 pinned in matrix_vm_test.go. Two
platform quirks, both worked around there: the kernel panics in
i8042_flush before init (initcall_blacklist=i8042_init), and the page size
is 16 KiB - the ELF writer aligns images to 64 KiB for p_offset/p_vaddr
congruence (e_flags carries the ABI bits, 0x43).
